# AmyNest Immutable Laws

**Status:** SUPREME · PERMANENT · BINDING  
**Authority:** Founder  
**Nature:** Law — not documentation, not architecture, not implementation  
**Survives:** V3 · V4 · V5 · and beyond  
**Oath:** [`FOUNDER_OATH.md`](./FOUNDER_OATH.md)  
**Index:** [`LAW_INDEX.md`](./LAW_INDEX.md)

Every feature, engine, SDK, AI provider, payment provider, module, screen, or redesign must obey this book.

If a change obeys no law here → **reject it**.

**Sources (extracted, not invented):** Design Constitution · Visual Constitution · Room Architecture · V3 Home Contract · Resident / Memory / Home API Laws · Founder Death Test · Founder Translation Law · Founder Implementation Law (certification tests).

Craft scales, tokens, and Platform programs are **subordinate**. They implement these laws. They do not redefine them.

---

# 1. Purpose

AmyNest exists to **hold a parent**.

It is not a dashboard.  
It is not a chatbot skin.  
It is not EdTech purple.  
It is not a suite of products.

AmyNest is a **Home** — one dwelling under one sky — where Amy is present, rooms share one air, and the parent crosses thresholds instead of opening apps.

The Home must outlive its creators.

---

# 2. Supreme Laws

*These can never change.*

---

### L01 — Home Law

| | |
|--|--|
| **Statement** | AmyNest is a Home. Every destination is a Room. The parent does not open apps; they cross thresholds. |
| **Why** | Application thinking creates products, shells, and weather that break Nest Presence. |
| **Failure** | A surface feels like an app, a tool, a dashboard, or a peer product instead of a room in one Home. |

---

### L02 — Nest Presence Law

| | |
|--|--|
| **Statement** | The identity of the Home is Nest Presence: held, quiet, warm, inevitable, human. |
| **Why** | Without one emotional climate, every screen invents its own brand of weather. |
| **Failure** | The parent feels processed, marketed, clinical, carnival-bright, or abandoned by chrome. |

---

### L03 — Permanence Law

| | |
|--|--|
| **Statement** | The Home is permanent. Frameworks, providers, and SDKs are temporary. |
| **Why** | Soul must not die when ChatPlatform, coach chrome, speech chrome, AI vendors, or stores change. |
| **Failure** | A temporary adapter is treated as irreplaceable identity, or replacing it is treated as redesigning AmyNest. |

---

### L04 — Ownership Law

| | |
|--|--|
| **Statement** | Rooms own emotion. Engines own execution. The Home owns continuity (and memory). |
| **Why** | Confused ownership creates second Amys, second shells, and rooms that execute instead of hold. |
| **Failure** | An engine owns chrome or memory; a room owns private truth; continuity is split across products. |

---

# 3. Home Laws

---

### L05 — Room Law

| | |
|--|--|
| **Statement** | Only these rooms exist: Threshold · Vestibule · Keep · Living Room · Practice Room · Study · Hearing Room · Continuity Room · Child’s Room. Work enters through an existing room. New rooms require Founder reopen of this book. |
| **Why** | Growth by inventing destinations becomes a bigger building. |
| **Failure** | A feature invents a new destination, peer Home, or forgotten page-name treated as a product. |

**Emotional jobs (fixed):**

| Room | Job |
|------|-----|
| Threshold | Arrive. Breathe. Decide to enter. |
| Vestibule | Be welcomed. Be known lightly. |
| Keep | Softly lock what must be kept. |
| Living Room | Meet the day with Amy. |
| Practice Room | Keep one short ritual. Leave relieved. |
| Study | Be seen for the longer path. |
| Hearing Room | Speak. Be answered. Be held. |
| Continuity Room | Choose to stay. |
| Child’s Room | The child’s small world — only when alive. |

---

### L06 — One Question Law

| | |
|--|--|
| **Statement** | Each room answers exactly one emotional question. A room that answers two has failed. |
| **Why** | Multiple questions recreate dashboards and feature catalogues. |
| **Failure** | A room competes with itself — two heroes, two jobs, or “also this product.” |

---

### L07 — Resident Law

| | |
|--|--|
| **Statement** | Every capability must become a better resident of an existing room — never a bigger building. If it needs its own identity, it belongs outside AmyNest. |
| **Why** | AmyNest grows by deepening rooms, never by adding products. |
| **Failure** | A feature ships with its own brand, nav, splash, voice, or visitor chrome. |

---

### L08 — Memory Law

| | |
|--|--|
| **Statement** | There is only one Amy. The Home owns memory. No room owns memory. Engines only read what the Home already knows (writes update Home, never a second Amy). |
| **Why** | Split memory makes Coach-Amy, Ask-Amy, and Mission-Amy — and forces the parent to re-introduce the child. |
| **Failure** | An engine or room keeps authoritative memory the rest of the Home cannot know. |

---

### L09 — Unity Law

| | |
|--|--|
| **Statement** | One atmosphere. One navigation. One shell. One visual language. No second Home. |
| **Why** | Dual chrome, dual nav, dual weather is app-switching — the death of Nest. |
| **Failure** | The parent feels they left AmyNest for another product, splash, or shell. |

# 4. Design Laws

---

### L10 — Law of Three

| | |
|--|--|
| **Statement** | One emotional hero · one obvious action · one supporting object. Nothing else competes. |
| **Why** | Competition is dashboard DNA. |
| **Failure** | Peer CTAs, badge clusters, feature grids, or multiple heroes above the fold. |

---

### L11 — Materials Law

| | |
|--|--|
| **Statement** | Only four materials: Atmosphere · Soft Plate · Sheet Glass · Bloom. No fifth without Founder amendment of supreme design authority. |
| **Why** | Material invention is a second visual language. |
| **Failure** | Hard kit cards, neon plastic, rainbow glass, stat tiles, or a new surface family. |

---

### L12 — Atmosphere Law

| | |
|--|--|
| **Statement** | Atmosphere is the first product. Same Nest world, different hour — never a new location or brand of weather per screen. Empty space is Ma; densifying to fit features is forbidden. |
| **Why** | Background invention and density recreate marketing and SaaS. |
| **Failure** | Random “special” backgrounds, filled emptiness, or weather that could belong to another brand. |

---

### L13 — Design Authority Law

| | |
|--|--|
| **Statement** | Nest Presence craft is one locked language (Design + Visual Constitutions). Local invention that contradicts it is a defect — not creative variation. Translate into Nest; do not redesign the product to invent a new look. |
| **Why** | Ad-hoc polish and “Nest-ification” opacity create false calm. |
| **Failure** | A screen invents type, buttons, nav, lighting, or materials outside the locked system — or restyles clutter instead of deleting it. |

*Method already approved:* DELETE → MERGE → WHISPER → EMPHASIZE. Never optimize before deleting.

# 5. Engineering Laws

---

### L14 — Adapter Law

| | |
|--|--|
| **Statement** | The Home is the primary API. Frameworks, AI providers, billing providers, and SDKs are adapters. Nothing outside the Home may define the user experience. |
| **Why** | When an SDK owns UX, AmyNest becomes that vendor’s skin. |
| **Failure** | Provider chrome, loading theatre, store DNA, or chatbot DNA defines what the parent sees as Nest. |

---

### L15 — Entry Law

| | |
|--|--|
| **Statement** | Every engine, module, feature, AI capability, or SDK enters through an existing room as a resident under Nest atmosphere, Nest shell, and Nest navigation. |
| **Why** | Side doors create visitors and second Homes. |
| **Failure** | A capability mounts as a peer app, classic dashboard peer, or route that abandons Home continuity. |

---

### L16 — Prepare Law

| | |
|--|--|
| **Statement** | Waiting is Nest prepare / reveal — never generator theatre, spinner carnival, or product splash as Nest language. |
| **Why** | Loading theatre announces a machine, not a Home. |
| **Failure** | “Generating plan…”, MEET-AI splash on Nest cold start, or chatbot spinner language inside care. |

---

# 6. Product Laws

---

### L17 — Growth Law

| | |
|--|--|
| **Statement** | AmyNest grows by deepening rooms, never by adding products. |
| **Why** | Product catalogues destroy Nest Presence and Resident Law. |
| **Failure** | Roadmap success measured by new modules shipped instead of rooms made more themselves. |

---

### L18 — Care and Commerce Law

| | |
|--|--|
| **Statement** | Care rooms hold the parent. Monetization lives in the Continuity Room — not inside care threads as quota theatre or upgrade cards. |
| **Why** | Commerce in care breaks trust and Hearing / Study / Practice soul. |
| **Failure** | Paywall, quota, or upgrade DNA interrupts being held. |

---

### L19 — Child Alive Law

| | |
|--|--|
| **Statement** | The Child’s Room is the child’s small world — only when alive. Hope without life is not a product to fake. |
| **Why** | A hollow child surface is a bigger building pretending to be a room. |
| **Failure** | Child destination ships as empty promise chrome or a separate app identity. |

---

### L20 — Functional Exit Law

| | |
|--|--|
| **Statement** | Functional exits (begin, sign in, get the app, privacy, terms, contact/support, restore where offered) may become whispers — they may never become impossible. Visual clutter may be deleted. |
| **Why** | Translation must not trap the parent or erase trust paths. |
| **Failure** | A required exit is removed, hidden beyond reach, or replaced by a dead end. |

---

### L21 — Care Law

| | |
|--|--|
| **Statement** | Every visible element must help a tired parent. If it does not — remove it. Replace clutter with calm, not with empty void. |
| **Why** | AmyNest serves fatigue and care, not engagement theatre. |
| **Failure** | Decorative chrome, reassurance spam, or blank broken emptiness. |

# 7. Founder Tests

*Run before ship. Any fail → reject or rewrite.*

| Test | Question | Fail if |
|------|----------|---------|
| **Death Test** | Can a new engineer continue AmyNest from supreme law alone without breaking its soul? | Work requires tribal Founder lore; soul not written |
| **Resident Test** | Does this make a better resident — or a bigger building? | Own identity, visitor chrome, new product |
| **Second Home Test** | Is there still only one shell, one nav, one atmosphere, one language? | App-switching feeling |
| **Care Test** | Does every visible element help a tired parent? | Clutter, theatre, void |
| **Memory Test** | Is there still only one Amy — Home memory, engines only reading? | Memory silo / second Amy |
| **Apple Test** | Would Apple accept this room’s restraint and inevitability? | Noise, peer CTAs, kit clutter |
| **Headspace Test** | Would Headspace accept this room’s calm and held climate? | Clinical cold, carnival, dashboard weather |
| **Parent Test** | Would a tired parent feel held here — identical Nest air to the rest of the Home? | Other-brand weather; processed, not held |

| Result | Action |
|--------|--------|

| Conflicts with any supreme law (L01–L04) | **Reject** — do not “amend by PR” |
| Needs its own identity | Belongs **outside** AmyNest |
