## Current defect

Production-facing `/routines` still presented as the old Routine product:

- Purple Parent Hub premium shell (`parent-hub-premium` / `#071126` + violet radials).
- SaaS header: “Routines” / “Daily schedules generated by AI”.
- Competing product tabs: Schedule / Forecast / Household / Why? / Safety.
- Neon chip selector and Zap “Generate routine…” CTA.
- Large blank band above first content (layout padding + always-on `mb-4` banner wrapper + hub `padding-top` safe-area stacked on the app header).
- `/routines/generate` already used the living R2/R3 room, so the parent walked **living AmyNest → old Routine product → living generation**.

## Root cause

`AppCore` routes `/routines` → `pages/routines/index.tsx` (`RoutinesList`). That page never consulted `isRoutineLivingV1Enabled()`. Generate (`pages/routines/generate.tsx`) did.

Blank space stacked from:

1. `Layout` `ScreenContainer` `py-4` on non-dashboard routes.
2. `NotificationNudgeBanner` wrapper always `mb-4` even when the banner returns `null`.
3. `.parent-hub-premium { padding-top: env(safe-area-inset-top) }` on top of `.app-header` safe-area.

Purple came from `PARENT_HUB_PAGE` → `index.css` `.parent-hub-premium`.

## Implementation map

`/routines` → `RoutinesList` → **legacy** (`PARENT_HUB_PAGE`, tabs, `RoutinePremiumCta`) **or living** (`RoutineLivingDashboard`) → CSS `routine-living-page` / sanctuary wash (same house as Welcome / Today Home / Care FE) → generate already `RoutineLivingOpening` / `RoutineLivingResult`.

Replacement: when `isRoutineLivingV1Enabled()`, render the living room. Keep listing, paywall, generate navigation, and child selection handlers unchanged.
