## Law

1. **UI improvements happen above the platform, never inside it.**  
2. If a UI change requires deleting or rewriting core platform modules, **the approach is wrong.**  
3. **Presentation changes only.**  
4. **Architecture remains intact.**

---

## Allowed (presentation layer)

- Visual hierarchy, materials, light, type *usage*, silence, copy rhythm  
- Room feeling (Threshold, Living Room, Practice, etc.) as presentation  
- Soft Plate / Bloom / Atmosphere / Sheet Glass application on surfaces  
- What is *shown*, *emphasized*, *whispered*, or *not rendered* in the UI — without removing platform capability  

## Forbidden

- Deleting Brain / Decision / Experience / SDK / Memory / Context / History / Registry / Routing / Analytics modules to “simplify” Nest  
- Rewriting decision or memory pipelines for visual goals  
- Route architecture changes for Room metaphors  
- Analytics or registry rewrites as part of UI recovery  
- Replacing platform behavior with presentation hacks that require core deletion  

---

## Room / Nest work under this lock

Nest Presence, Room Architecture, and translation DELETEs mean:

- **Delete visual silhouette** (neon, prompt walls as UI, dashboard chrome, empty tab *presentation*)  
- **Not delete** the underlying product systems that power care, memory, coach offers, entitlements, or events  

Capabilities stay. Costumes change.
